# 多文件源码工作台

## 用户约定

启动时为空；新建、打开和导入 KSH 都追加独立文件标签，不覆盖现有文档。主界面没有当前 KSH 名称或固定 VS/PS 配对。Ctrl+S 保存当前文件，另存为使用 Ctrl+Shift+S，全部保存是独立命令。关闭标签或窗口会检查每份源码的未保存内容，导出 KSH 不会清除源码修改标记。

导出先选择两个不同文件，分别作为 VS 和 PS，然后打开原生保存窗口。输出 `glow.ksh` 对应 effect `glow` 和内嵌源码名 `glow.vs` / `glow.ps`，不改变源文件名。扩展名用于默认分类，通用源码和未命名文件可在导出时选择阶段。

目前不提供实时渲染、参数面板、问题/输出面板或编辑时的语义检查。操作失败仍正常提示，后端构建校验继续保留。

## 模块边界

| 模块 | 职责 |
| --- | --- |
| `src/composables/useEditorWorkspace.js` | 独立文档列表、活动标签、左右编辑区、源码保存点、导入来源和导出快照 |
| `src/composables/useDocumentActions.js` | 打开、当前/全部保存、关闭确认、组合导出和忙状态；可注入 IO 测试 |
| `src/components/CodeEditor.vue` | 每个文件的 Monaco model、撤销历史、视图状态和编辑命令，不依赖阶段 |
| `src/components/DocumentDialog.vue` | VS/PS 单选列表、未保存确认、覆盖确认和跨来源元数据提示 |
| `src/components/AppDialog.vue` | Fluent 原生模态生命周期、取消和焦点恢复 |
| `src/App.vue` | 两行工作台、文件标签、菜单快捷键、聚焦和窗口关闭接入 |
| `src/utils/tauri-commands.js` | 原生文件选择、源码读写和 KSH 构建调用 |

工具按钮使用系统 `title` 提示。Fluent 3.1.3 的 tooltip 延迟回调在卸载后仍可能尝试显示 popover，因此不再注册该组件。文件标签采用标准 tab 语义；关闭按钮是相邻控件，不嵌套在标签按钮中。

当前未注册 GLSL 语义服务，Monaco 的 `occurrencesHighlight` 显式关闭，保留普通文本选择高亮。Monaco 0.52 的 symbol highlighter 在快速关闭标签时会将未处理的 Delayer 取消暴露为 `Canceled`；通过关闭无提供者的后台功能避免该路径，不使用全局异常屏蔽。

## 桌面标题栏

桌面窗口关闭系统 decorations，以 40px 自定义标题栏合并应用图标、菜单、工具和窗口控制；主界面只保留左上角一个应用图标。仅标题栏空白与应用图标接收拖动/双击最大化，交互控件不启动拖动。最小化、最大化/还原使用 Tauri 窗口 API，resize 事件同步最大化图标；关闭按钮调用 `close`，仍经过原有未保存确认，不直接销毁窗口。普通浏览器不显示不可用的窗口按钮。

标题栏配置变更需要重新构建并重启桌面版，网页刷新不能验证系统窗口行为。2026-09-07 已通过生产构建、全目标/功能 cargo check、浏览器模拟窗口 API 回归和桌面/窄窗口截图检查；实际 Windows 拖动、缩放与系统窗口行为尚未手动测试。

## 文件与异步操作

每份文档有稳定 `id`、`name`、`path`、`content` 和 `savedContent`。无路径的新文件以空文本为基线，非空即未保存；已有路径时与 `savedContent` 比较。导入 KSH 的两份源码没有独立路径，按暂存文件管理。导出历史仅用于记住选择和输出位置，不充当源码保存点。

同一 Windows 路径忽略大小写及斜杠差异，重复打开只激活已有标签，保留编辑。另存为不能覆盖另一已打开标签的路径，避免两个缓冲区争用同一文件。同名不同路径的文件仍独立，标签增加来源区分。

打开多个文件时先完成全部读取，再追加到工作台，读失败不留下半批结果。保存捕获单文件快照，磁盘成功写入后只记录该快照，期间继续输入仍为未保存。全部保存逐个进行，取消或失败保留已完成的保存，不声称整个操作具备事务性。

关闭当前文件只确认该文件；关闭全部或窗口确认所有未保存文件。放弃或保存期间如又产生编辑，会重新检查，不能用旧确认丢弃新内容。文件操作共用忙状态，原生选择窗口期间不允许重叠打开/关闭/导出操作。

`save_editor_source` 接收不含阶段的路径、内容和 `force`，支持 `.vs`、`.ps`、`.glsl`、`.txt`。后端检查 NUL 和扩展名，复用已有原子写入逻辑；未完成语法仍可保存。旧阶段写入命令和旧构建接口保持兼容。

## KSH 来源与命名

每次导入生成独立 origin ID，完整 KSH 元数据在工作台内部保存，文档只记录 origin ID、原路径和原阶段。关闭来源的所有文档后释放元数据。再次导入不覆盖已有同路径同阶段标签，但补回的阶段属于新的导入，不能与旧缓冲区假定共享同一份磁盘版本。

只有同一 origin 的原始 VS 和 PS 按原阶段组合时，`exportSnapshot(vsId, psId)` 才提供完整 `base_ksh`。跨来源组合返回 `rebuildMetadata: true`，用户确认后根据源码重建，不自动混合默认值或未知记录。选择阶段后捕获源码快照，文件选择与覆盖确认完成后重新核对；无关标签的编辑不影响导出。

工作台调用 `build_ksh` 时启用 `name_from_output`。后端从输出 stem 自动生成三个名称，保留兼容的其他元数据；默认关闭该选项，以兼容旧接口原本保留导入 effect 的行为。

## 后续预览

预览可以复用 `candidates(stage)` 和 `exportSnapshot(vsId, psId)` 选择源码，但使用自己的临时组合与编译状态，不能强制配对主界面的文件。编译结果应用前检查两个文档身份和内容，避免旧结果覆盖新编辑。

纹理、时间、相机、运行时 uniform 数值属于独立预览状态，不影响源码保存点。实时诊断只在预览能力接入后再增加。编辑器内预览成功不等于游戏专用管线兼容。
